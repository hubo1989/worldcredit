## 1. 项目概述

### 1.1 是什么

**WorldCredit** 是一个面向家庭的信用卡管理 PWA + 管理后台。一个人注册一个账号，管理全家所有持卡人的信用卡——账单、还款、权益、优惠、额度，配 AI 辅助录入和 PWA 推送提醒。

- **手机端 PWA**：日常查看和操作，Android/iOS 免安装
- **Web 管理后台**：平台管理员维护银行目录、卡产品库、优惠活动、权益定义

### 1.2 用户角色

| 角色 | 入口 | 权限 |
|------|------|------|
| **家庭用户** | 手机端 PWA | 一个账号管理全家持卡人。全部持卡人 CRUD、信用卡 CRUD、账单/还款/权益/优惠的增删改查 |
| **平台管理员** | Web 后台 | 维护平台基础数据：银行目录、卡产品库、优惠活动定义、权益定义。看平台运营统计，**不接触家庭账目明细** |

持卡人是**家庭档案**，不是登录账号。`card_holders.managed_by` 指向家庭用户。

### 1.3 技术栈

| 层级 | 技术 | 说明 |
|------|------|------|
| 前端框架 | React 19 + vinext | Cloudflare 的 Vite + Next.js 实现 |
| UI 组件库 | MUI 7 + Emotion | Material Design 组件，本需求中重新定义设计 token |
| 后端平台 | InsForge | Agentic 后端，Postgres + Auth + Storage |
| PWA | vite-plugin-pwa | Service Worker + Web Push 通知 |
| 邮件解析 | Cloudflare Email Worker | 监听 Gmail 账单邮件，解析为结构化数据 |
| 部署 | Cloudflare Workers | vinext deploy |

### 1.4 当前项目状态

已有功能（代码盘点）：
- 持卡人 / 信用卡 / 账单 / 还款 CRUD
- 额度实时计算（从未还账单推导，不存冗余字段）
- 优惠活动 + 权益 + 使用记录
- AI 助手页面（SmartInputArea / ScenarioQuickQuestions）→ **本次重新定位为表单内嵌 AI 填充**
- Gmail 账单邮件导入（email-worker + gmail-ledger）
- PWA Web Push 还款提醒
- 后台仪表盘 + 卡产品/银行/优惠/权益管理 + AiCompleteButton
- 登录注册、提醒偏好、显示偏好

项目当前使用 MUI 默认风格。**本次设计规范定义了新的视觉系统**，agent 在执行任务时需逐步迁移到新 token。

## 3. 首页设计 · 统计看板

### 3.1 页面结构

```
[持卡人分段]  全部 | A | B | C
[主指标卡]    总待还款 ¥20,740（含逾期 ¥6,200 · 未来 7 天 ¥6,480）
[指标网格 2×2]
  已逾期 ¥6,200（红）        未来 7 天待还 ¥6,480（金） [7/14/30 天切换]
  总欠款 ¥45,740（可展开）    未出账单 ¥1,200（预计 / 暂无数据占位）
[账户] 全部 8 张 · A 3 · B 3 · C 2（可点击切换）
[金刚区] 记一笔 | 优惠 | 权益 | 导入账单
[逾期明细] 仅未还逾期账单列表（无逾期时显示空态"本月无逾期"）
```

### 3.2 六大指标定义

| 指标 | 数据口径 | 状态 |
|------|---------|------|
| **总待还款** | SUM(未还账单金额) | 主数字，大号展示 |
| **已逾期总额** | 已过还款日未还清的账单合计 | 红色；无逾期 → 绿色 ¥0 |
| **未来 N 天待还** | 还款日在未来 N 天的账单合计 | 金色；N 可切换 7/14/30 |
| **总欠款** | 分期剩余本金 + 贷款剩余本息 + 普通未还 | 可展开三项明细 |
| **未出账单** | 已入账未出账单的消费（如能获取） | 无法获取 → "暂无数据"占位 |
| **总账户数** | 各持卡人卡数合计 | chips 展示各持卡人卡片数 |

### 3.3 交互行为

- 持卡人分段切换（全部/A/B/C）：**全部指标 + 账户数 + 逾期明细联动更新**，带 260ms 淡化过渡
- 未来 N 天切换（7/14/30）：指标实时变化
- 总欠款可展开/收起（点击展开 分期本金 / 贷款本息 / 普通未还）
- 逾期明细可点击跳转账单页
- 导入账单按钮：演示错误态（网络不可用 + 重试）+ 重试成功

### 3.4 数据口径注意事项

- **待还金额只算 `status != paid` 的账单**，已还清的不计入任何首页指标
- **总欠款 = 分期本金 + 贷款本息和 + 普通未还**。分期和贷款需要数据模型支撑（当前可能仅有贷款类卡片，分期需要新增 installments 表或从账单标记推导）
- **未出账单**：Gmail 邮件解析中可能存在"已入账但未出账单"的交易，标记为 `unbilled`；获取不到时显示占位，不纳入统计
- **免息期 = 还款日 − 账单日**（天数），用于排序

## 4. 账单页设计

### 4.1 页面结构

```
[维度切换]  按持卡人 | 按银行（分段控件）
[标签行]    全部 | A | B | C（按维度动态变化）
[月份切换]  ‹ 2026 年 8 月 ›
[排序]      还款日近→远 | 免息期最长
[列表]      按维度分组渲染
```

### 4.2 双维度分组

#### 按持卡人
标签全部/A/B/C。列表直接按顺序渲染，逾期置顶。

#### 按银行
标签为全部银行/招商/中行/中信/浦发/交行/广发等。**分组渲染**：
- 组头：`招商银行 · 2 账户 · 待还 ¥9,600`（深蓝底白字）
- 组内每张卡一条账单行
- 单银行单账户：独立成组
- 单银行多账户（如招商 2 卡、中行 2 卡）：同一组头下多个账单行

### 4.3 账单卡片信息

每条账单卡展示：
- **第一行**：卡片名 + 持卡人/银行徽章 + 金额（等宽数字） + 状态徽章（绿已还/黄部分/红逾期/蓝待还）
- **第二行**：账单日 每月 X 日 · 还款日 每月 Y 日 · **免息 N 天**（金色高亮）

### 4.4 排序

- **还款日近→远**（默认）：逾期账单置顶，其余按还款日升序
- **免息期最长**（切换「免息期最长」标签）：按 `grace`（免息天数）降序排列

### 4.5 月份切换

- 月份切换器，默认加载当月
- 切换月份走 350ms 骨架加载
- 某月无账单 → 空态：「这个月没有账单 · 可以手动录入或导入」+ 引导按钮

### 4.6 账单详情页（二级页面）

从账单卡片点击进入。信息结构：
- 头部：卡名 + 持卡人/银行 + 金额 + 状态徽章
- **金额四格**：应还 / 最低 / 已还 / 剩余（等宽数字）
- **账单周期**：`账单周期 7/16 – 8/15 · 尾号 2201`
- **日期信息**：`账单日 每月 15 日 · 还款日 每月 10 日 · 免息 25 天`
- **还款记录**：时间线列表（无还款时 → 空态"尚未还款"）
- **操作按钮**：去还款 / 查看卡片详情

### 4.7 信用卡详情页（二级页面）

从账单详情「查看卡片详情」进入。信息结构：
- **卡面**：银行渐变块 + 卡种名 + 掩码卡号 + 持卡人
- **额度三格**：总额度 / 已用（金） / 可用（绿）
- **日期与费用**：账单日 / 还款日 / 最长免息 / 年费 / 币种
- **最近账单**：该卡当月账单卡片（可点击回账单详情）
- **权益进度**：该卡挂载的权益 + 使用进度

- **后台**：AiCompleteButton 组件已在 admin 表单中使用，视觉统一为金色「AI 填充」标识

## 8. 数据治理 · 多来源一致性

### 8.1 来源模型

每条账单 / 卡片记录带 `source` 字段：

| source | 含义 | 冲突权限 |
|--------|------|---------|
| `email` | 邮件导入自动解析 | L1 可自动合并；关键字段差异 L2 确认 |
| `manual` | 手动录入/编辑 | 用户手动改过 → `user_edited=true` → L3 永不覆盖 |
| `ai` | AI 智能填充 | 仅预填；保存后即视为 `manual`，无独立冲突源 |

### 8.2 幂等与匹配

- **账单唯一键**：`card_id + bill_month + statement_date`（同卡同月仅一份账单）
- **导入前查重**：命中 → 更新候选（不新建）；未命中 → L1 创建
- **卡片匹配键**：银行 + 卡号后四位 → 命中关联已有卡；未命中 → 进「新卡认领」队列

### 8.3 三层冲突处理

| 层级 | 触发 | 行为 |
|------|------|------|
| L1 自动合并 | 新账单，无冲突 | 直接创建，来源=email，状态待确认 |
| L2 需确认 | 关键字段不一致（金额/还款日） | 不自动改；冲突卡：「邮件 X / 你的 Y」三选一 |
| L3 永不覆盖 | 字段 user_edited | 仅提示差异，不改值，用户再次确认后才更新 |

### 8.4 UI 落点

- 账单详情显示来源徽章 + 最近更新信息
- 冲突卡：三选项（采用邮件 / 保留我的 / 手动对比），同类差异不重复问
- 新卡认领：首页/账单页横幅「发现 1 张新卡」→ 认领（选持卡人）或忽略
- 撤销导入：邮件源账单可一键撤销（删除账单 + 关联还款）

## 9. 数据模型中注意事项

### 9.1 已用额度

**不从存储字段读取**，从最新未还账单实时计算：
```
used = SUM(bills.bill_amount - payments.amount) WHERE status != 'paid'
```
不许存冗余 `used_amount` 字段。

### 9.2 还款状态

由 payments 汇总 + due_date 比较实时推导（不存储 status 快照）：
- paid ≥ bill_amount → `paid`
- paid > 0 → `partial`  
- due_date 已过且 paid < bill_amount → `overdue`
- 其余 → `unpaid`

### 9.3 权益周期重置

剩余 = quota − COUNT(usages) WHERE used_at IN current_period。按时间范围查询自然实现周期重置，无需清数据。

### 9.4 免息期

`grace = payment_due_value − billing_day`（还款日 − 账单日，天数）。需在账单查询中作为计算字段返回，用于排序。

### 9.5 总欠款

需要新增或复用以下数据：
- **分期记录**（installments）：分期金额、剩余本金、分期期数
- **贷款记录**（现有的贷款类卡片）：本金 + 利息 + 剩余期数
- 总欠款 = 普通未还 + SUM(分期剩余本金) + SUM(贷款剩余本息)

### 9.6 邮件导入草稿队列

邮件解析的结果不进 `bills` 表直接落库，而是进 `email_parse_logs`（或其他暂存表）作为草稿。经过查重/匹配/冲突判定后，用户确认（或 L1 自动）才落库打 `source` 标签。
