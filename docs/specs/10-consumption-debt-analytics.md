# Spec: 消费与负债分析

**状态**: 路线图规划  
**日期**: 2026-04-29  
**相关模块**: 首页、持卡人统计、账单、明细、权益、优惠

## 目标

把已有账单、还款、明细、权益和优惠数据转化为趋势与洞察，帮助管理员看清家庭整体信用卡负债变化，并按成员、银行、卡片定位异常。

## 用户故事

作为管理员，我希望查看家庭总待还、已还、逾期和额度使用率趋势，以便判断整体财务压力。

作为管理员，我希望按成员、银行、卡片分析消费和负债，以便定位高风险来源。

作为用户，我希望看到消费分类统计，以便理解钱花在哪里。

作为用户，我希望看到权益使用率和优惠使用情况，以便评估信用卡是否值得保留。

作为成员，我希望只查看自己的分析数据，以便了解个人用卡情况。

## 范围

MVP 包含：

- 家庭、成员、银行、卡片维度筛选。
- 月度账单趋势。
- 待还金额、已还金额、逾期次数。
- 额度使用率趋势。
- 消费分类统计。
- 权益使用率。
- 优惠使用次数。
- 高风险提示。

不包含：

- 预算管理。
- 银行流水接入。
- 预测模型。
- 投资或征信建议。

## 指标定义

### 负债指标

- `total_bill_amount`: 周期内账单总额。
- `pending_amount`: 未还清账单金额。
- `paid_amount`: 周期内还款总额。
- `overdue_count`: 逾期账单数。
- `utilization_rate`: 未还清账单金额 / active 卡总额度。

### 消费指标

- 按 `bill_items.category` 聚合金额。
- 退款金额单独展示或从消费中抵扣，需要在 UI 中说明。
- 明细缺少分类时归为“未分类”。

### 权益与优惠指标

- `benefit_usage_rate`: 使用次数 / 权益额度。
- `promo_usage_count`: 优惠使用次数。
- 后续可加入节省金额。

## 页面设计

建议新增 `/analytics` 或扩展持卡人统计页。

页面结构：

- 顶部筛选：时间范围、成员、银行、卡片。
- 总览指标：账单总额、待还、已还、逾期数、额度使用率。
- 趋势图：近 6/12 个月账单和还款趋势。
- 分类图：消费分类占比。
- 风险列表：高额度使用、逾期、连续高消费月份。
- 权益/优惠模块：使用率、即将过期但未使用项。

## 数据与 API

建议新增聚合 API：

- `getAnalyticsSummary(filters)`
- `getMonthlyDebtTrend(filters)`
- `getCategoryBreakdown(filters)`
- `getBenefitUsageAnalytics(filters)`
- `getPromoUsageAnalytics(filters)`

过滤字段：

- `from_month`
- `to_month`
- `holder_id`
- `bank_name`
- `card_id`

第一版可以前端拉取后聚合，但数据量增长后应迁移到数据库 RPC 或视图。

## 权限

- 管理员可按全家维度分析。
- 成员只能分析自己的卡片和账单。
- 导出的分析数据也必须遵循相同权限。

## 边界情况

- 信用额度为 0 时额度使用率显示为空或 0，避免除零。
- 跨币种第一版按原币种分组展示，不做汇率换算。
- 无分类明细归为“未分类”。
- 退款和调整项需要在图表中明确处理方式。
- 逾期状态既可来自 `status = overdue`，也可由 `due_date < today` 且未还清动态判断。

## 验收标准

- 管理员可以查看家庭级、成员级、银行级、卡片级分析。
- 成员只能查看自己的分析。
- 近 6/12 个月趋势计算正确。
- 额度使用率、待还金额、逾期数与账单数据一致。
- 分类统计能处理未分类、退款和空数据。
- 高风险提示至少覆盖逾期和额度使用率过高。
