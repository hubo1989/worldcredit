# Spec: 优惠与权益筛选优先级

> **历史规格，已由 [WC-BEN-12](./12-credit-card-benefits-opportunities.md) 的“我的可用机会”和[技术附录](./12-credit-card-benefits-opportunities-technical.md)替代。** 新实现聚合个人账户、配额和资格；不使用全站目录条数或前端临时拼接判断今天可用。

**状态**: 路线图规划  
**日期**: 2026-04-29  
**相关模块**: 优惠页、卡片详情、权益列表

## 目标

让优惠和权益从“静态记录”升级为“可行动机会”。用户可以按银行、卡片、有效期、使用状态筛选，并优先看到即将过期、高价值或低使用率的机会。

## 用户故事

作为用户，我希望筛选进行中的优惠，以便只看现在能用的活动。

作为用户，我希望按银行或卡片筛选优惠与权益，以便快速找到某张卡可用的机会。

作为用户，我希望系统优先展示即将过期或快用完的权益，以便减少浪费。

作为管理员，我希望从全家视角查看所有权益和优惠机会，以便安排谁该优先使用。

作为成员，我希望只看到自己可用的权益和优惠，以便列表更聚焦。

## 范围

MVP 包含：

- 优惠页增加筛选器。
- 卡片详情显示该卡相关优惠。
- 独立“机会”视图或在优惠页合并展示权益与优惠。
- 排序优先级：已逾期/已过期置后，即将到期置前，高剩余额度置前。
- 每个机会展示原因标签。

不包含：

- 自动推荐最佳卡。
- 复杂价值评分模型。
- 外部银行活动抓取。

## 功能需求

### 筛选器

支持筛选：

- 类型：优惠、权益、全部。
- 银行。
- 卡片。
- 状态：可用、即将到期、已过期、已用尽。
- 优惠类型：满减、折扣、积分、返现。

筛选状态应保留在 URL query，便于返回时恢复。

### 排序

默认排序：

1. 今天截止。
2. 3 天内到期。
3. 7 天内到期。
4. 权益剩余额度少且即将过期。
5. 其他可用项。
6. 未开始。
7. 已用尽。
8. 已过期。

### 机会卡片

统一展示：

- 名称。
- 类型。
- 银行/卡片。
- 有效期。
- 剩余额度或使用次数。
- 条件或说明。
- 状态标签。
- 操作按钮：记录使用、查看卡片、查看账单。

## 数据与 API

建议聚合模型：

```ts
interface Opportunity {
  id: string
  type: 'promo' | 'benefit'
  title: string
  bank_name: string
  card_id?: string
  card_name?: string
  status: 'available' | 'expiring' | 'expired' | 'used_up' | 'not_started'
  starts_at?: string
  ends_at?: string
  used_count?: number
  quota?: number
  priority_score: number
  reason_tags: string[]
}
```

建议 API：

- `getOpportunities(filters): Promise<Opportunity[]>`
- `getCardOpportunities(cardId): Promise<Opportunity[]>`

第一版可以在前端组合 `getPromosForCards`、`getBenefitsWithUsage`。

## 权限

- 管理员聚合自己管理范围内所有卡片机会。
- 成员只聚合自己卡片机会。
- 银行级优惠只在用户拥有该银行信用卡时展示。

## 边界情况

- 没有结束日期的优惠视为长期有效，但排序低于明确即将到期项。
- 没有到期日的权益不进入“即将到期”。
- 权益额度用尽后不可记录使用。
- 优惠未开始时不可记录使用。
- 同一银行多张卡可用同一银行级优惠时，记录使用时要求选择实际卡片。

## 验收标准

- 用户可以按银行、卡片、状态筛选优惠和权益。
- 默认列表优先展示近期需要处理的机会。
- 管理员和成员的数据范围符合权限。
- 卡片详情可以看到该卡相关机会。
- 记录使用后机会状态和剩余额度刷新。
