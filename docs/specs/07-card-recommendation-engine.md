# Spec: 用卡建议引擎

**状态**: 路线图规划  
**日期**: 2026-04-29  
**相关模块**: 优惠、权益、信用卡、规则引擎

## 目标

用户输入消费场景、金额、币种或商户类型后，系统推荐最合适的信用卡、优惠或权益，并解释推荐原因。第一版采用规则引擎，不引入复杂 AI 决策。

## 用户故事

作为用户，我希望输入一笔消费金额和场景后知道该刷哪张卡，以便最大化优惠或权益价值。

作为用户，我希望推荐结果说明原因，以便我能判断建议是否可靠。

作为成员，我希望推荐只基于我自己的卡片，以便不会看到其他人的卡。

作为管理员，我希望可以从全家卡片中获得推荐，以便帮家庭成员安排用卡。

## 输入

MVP 输入项：

- 消费金额，必填。
- 币种，默认 CNY。
- 消费场景，选填，如餐饮、出行、酒店、境外、网购、商超。
- 商户关键词，选填。
- 消费日期，默认今天。
- 使用人，管理员可选成员；成员固定为自己。

## 输出

推荐结果包含：

- 推荐信用卡。
- 可叠加优惠。
- 可使用权益。
- 推荐理由。
- 注意事项。
- 备选卡片。

示例理由：

- 该卡有 7 天内到期的餐饮满减优惠。
- 该卡还有 2 次机场贵宾厅权益。
- 该卡币种与消费币种匹配。
- 该卡额度充足。

## 规则

第一版评分规则：

- 优惠活动匹配银行或卡片：+40。
- 优惠类型与场景匹配：+20。
- 优惠即将到期：+10。
- 权益场景匹配且有剩余额度：+25。
- 权益即将到期：+10。
- 币种匹配：+10。
- 卡片可用额度覆盖消费金额：+15。
- 卡片状态非 active：直接排除。
- 已过期优惠或用尽权益：不计分。

总分相同则按即将到期机会优先，再按可用额度高低排序。

## 功能需求

### 推荐入口

可以放在优惠页顶部或新增“建议”页：

- 表单输入消费信息。
- 点击“获取建议”后展示推荐列表。

### 推荐列表

至少展示前三个结果：

- 第一推荐突出显示。
- 每个结果展示卡片、分数、理由标签、可用优惠/权益。
- 展示“不推荐原因”，例如额度不足、优惠已过期、权益已用尽。

### 可解释性

推荐结果必须由规则生成，并保留规则命中明细。不得只展示一个不可解释结论。

## 数据与 API

建议新增纯函数：

- `scoreCardForPurchase(card, opportunities, input): RecommendationResult`

建议 API：

- `getCardRecommendations(input): Promise<RecommendationResult[]>`

数据来源：

- `credit_cards`
- `bills`，计算已用额度。
- `promos`
- `benefits`
- `benefit_usages`
- `promo_usages`

## 权限

- 管理员可以选择任一自己管理的持卡人或全家卡片。
- 成员只能基于自己的卡片获得建议。
- 推荐结果不得泄露不可访问卡片、优惠或权益。

## 边界情况

- 没有任何匹配机会时，仍推荐额度充足且状态正常的卡。
- 所有卡额度不足时提示“无合适卡片”，并展示原因。
- 金额小于等于 0 时禁止提交。
- 币种不匹配时不排除，但降低优先级。
- 优惠条件文本无法结构化判断时，只作为弱匹配理由。

## 验收标准

- 用户输入金额和场景后能获得排序后的卡片建议。
- 推荐理由可解释且来自明确规则。
- 成员不会看到其他成员卡片。
- 额度不足、卡片冻结、优惠过期、权益用尽会影响推荐结果。
- 推荐逻辑有单元测试覆盖核心评分规则。
