# Spec: 优惠使用记录

**状态**: 已建模，界面不完整  
**日期**: 2026-04-29  
**相关表**: `promos`, `promo_usages`, `credit_cards`  
**相关 API**: `lib/api/promos.ts`

## 目标

让用户可以记录优惠活动的实际使用情况，形成“活动定义 -> 可用活动 -> 使用记录”的闭环。当前系统已经有 `promo_usages` 表和 `recordPromoUsage` API，但优惠页没有明显的记录使用入口。

## 用户故事

作为用户，我希望在优惠活动卡片上记录“已使用”，以便系统统计这个活动是否已经被用过。

作为用户，我希望记录使用优惠时选择实际使用的信用卡，以便后续分析哪张卡带来了优惠收益。

作为用户，我希望填写备注，以便记录订单号、商户、节省金额或特殊条件。

作为管理员，我希望查看某个优惠的使用次数和使用记录，以便判断活动是否值得继续关注。

## 范围

MVP 包含：

- 优惠活动卡片展示已使用次数。
- 进行中且未过期的优惠展示“记录使用”按钮。
- 记录使用时支持选择信用卡和填写备注。
- 成员只能选择自己可访问的卡片。
- 管理员可以删除优惠活动；删除会级联删除使用记录。

不包含：

- 自动计算节省金额。
- 优惠使用上限自动拦截复杂规则。
- 订单、商户、支付流水集成。
- 自动匹配账单明细。

## 功能需求

### 优惠列表展示

优惠卡片增加：

- 使用次数。
- 最大可用次数 `max_uses`，如果存在则展示 `used_count / max_uses`。
- 当前状态：进行中、今天截止、即将截止、已过期、已用尽。
- “记录使用”按钮。

### 记录使用

用户点击“记录使用”后打开表单：

- 信用卡，选填或必填取决于优惠是否绑定卡片。
- 使用日期，默认为今天。
- 备注，选填。

提交后写入 `promo_usages` 并刷新优惠列表。

### 使用限制

- 优惠已过期时不可记录使用。
- `max_uses` 存在且已达到上限时不可记录使用。
- 成员不能选择不属于自己的卡片。
- 银行级优惠 `card_id = null` 时，用户可从同银行可访问卡片中选择实际使用卡。

## 权限

- `admin`: 可创建、删除优惠；可记录任意自己管理范围内卡片的优惠使用。
- `member`: 可查看与自己卡片或银行匹配的优惠；可记录自己的优惠使用。
- `member` 不可创建、编辑、删除优惠定义。

## 数据与 API

现有 API：

- `getPromos`
- `getActivePromos`
- `getPromosForCards`
- `recordPromoUsage`
- `getPromoUsages`

建议新增：

- `getPromosWithUsage(cards, activeOnly)`，一次返回优惠及使用次数，避免 N+1 查询。
- `recordPromoUsage(promoId, input: { card_id?: string; used_at?: string; note?: string })`。

`promo_usages` 建议后续扩展字段：

- `saved_amount NUMERIC`，记录节省金额。
- `currency TEXT`，记录节省金额币种。

## 边界情况

- 优惠没有结束日期时视为长期有效。
- 优惠开始日期晚于今天时展示“未开始”，不可记录使用。
- 优惠已过期时只读展示。
- `max_uses` 为空时不限制次数。
- 记录使用失败时保留弹窗内容并展示错误。
- 删除优惠时提示使用记录也会删除。

## 验收标准

- 用户可以从优惠列表记录一次优惠使用。
- 使用记录保存后，优惠卡片使用次数立即更新。
- 成员无法给其他成员的卡片记录优惠使用。
- 已过期、未开始、已用尽活动不能记录使用。
- 管理员和成员看到的数据范围符合各自权限。
