# Spec: 粘贴账单文本批量录入

**状态**: 路线图规划  
**日期**: 2026-04-29  
**相关模块**: 账单创建、账单明细、校验

## 目标

降低手动录入账单和明细的成本。用户可以粘贴账单文本或表格文本，系统解析为多条明细，自动计算合计，并在用户确认后创建账单和账单明细。

## 用户故事

作为管理员，我希望粘贴银行账单文本后批量生成明细，以便不必逐条手动录入。

作为管理员，我希望系统校验明细合计和账单金额是否一致，以便发现录入错误。

作为管理员，我希望在保存前编辑解析结果，以便修正格式不一致的账单文本。

作为成员，我希望第一版不能创建账单，以便基础账单数据仍由管理员维护。

## 范围

MVP 包含：

- 在添加账单表单中增加“粘贴明细”入口。
- 支持按行解析交易日期、说明、金额、分类。
- 支持用户编辑解析后的明细。
- 自动计算明细合计。
- 明细合计与账单金额不一致时提示。
- 用户确认后随账单一起写入 `bill_items`。

不包含：

- OCR。
- PDF 解析。
- 邮件导入。
- LLM 自动识别。
- 自动分类模型。

## 输入格式

第一版支持宽松文本格式：

```text
2026-04-01 星巴克 38.00 餐饮
2026-04-03 地铁 12.00 出行
2026-04-05 退款 -20.00 退款
```

也支持制表符或多个空格分隔：

```text
2026-04-01    星巴克    38.00    餐饮
```

解析策略：

- 行首日期匹配 `YYYY-MM-DD` 或 `YYYY/MM/DD`。
- 行尾第一个可解析金额作为金额。
- 日期和金额之间作为描述。
- 金额后的文本作为分类。

## 功能需求

### 粘贴入口

账单表单新增：

- “粘贴明细”按钮。
- 多行文本框。
- “解析”按钮。

### 解析预览

解析后展示表格或移动端列表：

- 交易日期。
- 商户或说明。
- 金额。
- 分类。
- 错误提示。

用户可编辑、删除、新增行。

### 校验

保存前校验：

- 至少账单基础字段有效。
- 每条明细说明和金额有效。
- 日期格式有效或允许为空。
- 明细合计和账单金额不一致时显示警告，但允许用户确认保存。

## 数据与 API

复用现有 `createBill` 的 `items` 参数。

建议新增前端工具函数：

- `parseBillItemsFromText(text): ParsedBillItem[]`
- `validateBillItemDrafts(items): ValidationResult`

明细字段映射：

- `transaction_date`
- `description`
- `amount`
- `category`
- `item_type`: 金额小于 0 时为 `refund`，否则为 `purchase`。
- `source`: `manual`。

## 权限

- 管理员可创建账单和批量明细。
- 成员不可创建账单。

## 边界情况

- 空行忽略。
- 无法解析金额的行标记错误。
- 日期缺失时允许保存，但提醒会影响利息估算准确性。
- 明细合计为负数时禁止作为正常账单保存。
- 重复粘贴不会自动去重，用户确认前可删除。
- 账单金额和明细合计差异大于 0.01 时提示。

## 验收标准

- 管理员可以粘贴多行文本并解析为账单明细。
- 解析结果可编辑。
- 明细合计实时展示。
- 合计与账单金额不一致时有明确警告。
- 保存后账单和明细同时入库。
- 解析工具有单元测试覆盖日期、金额、退款、异常行。
