# Spec: 持卡人邮箱自动绑定成员账号

**状态**: 已建模，界面不完整  
**日期**: 2026-04-29  
**相关表**: `users`, `card_holders`  
**相关 API**: `autoBindHoldersByEmail`, `bindHolderToUser`, `getMyHolderProfile`

## 目标

让管理员通过持卡人邮箱把家庭成员档案绑定到成员账号，使成员登录后只看到自己的持卡人、卡片、账单、权益和优惠数据。当前 API 已支持按邮箱自动绑定，但缺少清晰的管理入口和反馈。

## 用户故事

作为管理员，我希望给持卡人填写邮箱后点击自动绑定，以便系统把该持卡人关联到同邮箱成员账号。

作为管理员，我希望看到哪些持卡人已绑定、未绑定、绑定失败，以便继续处理成员权限。

作为成员，我希望登录后只看到绑定到我的持卡人档案，以便管理自己的信用卡数据。

作为系统，我希望邮箱匹配过程可重复执行且不会覆盖已有绑定，以便管理员可以安全地多次尝试。

## 范围

MVP 包含：

- 持卡人列表或持卡人详情展示绑定状态。
- 管理员可手动触发“按邮箱自动绑定”。
- 自动绑定只处理当前管理员管理的、`auth_user_id` 为空、且填写了邮箱的持卡人。
- 绑定结果展示成功数量和未匹配列表。
- 管理员可手动解绑或重新绑定需单独确认。

不包含：

- 邀请链接。
- 管理员代建成员密码。
- 邮件通知。
- 多个持卡人绑定同一个成员账号的复杂家庭账户模型。

## 功能需求

### 绑定状态展示

持卡人列表和详情页展示：

- 未填写邮箱。
- 等待绑定。
- 已绑定成员账号。
- 匹配失败。

如果已绑定，展示成员邮箱或脱敏邮箱。

### 自动绑定

管理员点击“自动绑定成员账号”后：

1. 查询当前管理员管理的持卡人。
2. 找出 `auth_user_id IS NULL` 且 `email` 非空的记录。
3. 查询 `users.email`。
4. 邮箱小写匹配。
5. 成功后写入 `card_holders.auth_user_id`。
6. 返回成功数量和未匹配邮箱。

### 手动绑定

管理员可以在持卡人详情页输入或选择成员账号进行绑定。第一版可以不做模糊搜索，只支持输入成员邮箱并查找。

### 解绑

管理员可以解除绑定。解除前提示成员将不再能访问该持卡人的数据。

## 权限

- 只有管理员可以绑定、解绑。
- 成员不能修改自己的绑定关系。
- 成员只能通过 RLS 读取 `auth_user_id` 指向自己的持卡人链路数据。

## 数据与 API

复用字段：

- `card_holders.email`
- `card_holders.auth_user_id`
- `users.email`
- `users.role`

建议 API：

- `autoBindHoldersByEmail(adminUserId): Promise<{ boundCount: number; unmatched: string[] }>`
- `bindHolderByEmail(holderId, email): Promise<CardHolder>`
- `unbindHolder(holderId): Promise<CardHolder>`

当前 `autoBindHoldersByEmail` 只返回数量，建议增强为返回明细，便于 UI 展示。

## 边界情况

- 邮箱大小写不同应视为相同。
- 邮箱为空时跳过。
- 已绑定持卡人默认不覆盖。
- 一个邮箱匹配多个业务用户时应拒绝自动绑定并提示人工处理。
- 一个成员邮箱对应多个持卡人时默认允许或禁止需要产品决策；MVP 建议禁止并提示人工确认。
- 成员账号不存在时提示“未注册”。

## 验收标准

- 管理员可以看到每个持卡人的绑定状态。
- 管理员可以一键按邮箱自动绑定成员账号。
- 自动绑定不会覆盖已有绑定。
- 成员登录后只看到自己的持卡人和关联数据。
- 未绑定成员登录后看不到任何持卡人数据或看到明确空状态。
- 成员无法越权访问其他持卡人的 URL。
